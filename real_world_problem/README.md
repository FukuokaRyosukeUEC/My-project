# 138次元・配置モチーフ制約付き Memetic NSGA-II

添付コードの目的関数と来場者エージェントを変更せず、46配置物の `(x, y, theta)` を
直接探索する1層型の Memetic NSGA-II です。設計変数は `46 × 3 = 138` 個です。

この版で追加したのは、次の3点だけです。

1. 人が受け入れやすい配置を探索中から保証する「配置モチーフ制約」
2. 5世代ごとの非劣解近傍探索（Memetic探索）
3. シミュレーション結果を変えない実装上の高速化

最適化後に座標を整える修復処理はありません。保存される配置とシミュレーションで
評価された配置は同一です。

## 変更していないもの

### 目的関数

添付された `metrics.py` の2目的をそのまま使用します。

- `f_move`: 来場者1人当たりの平均自由歩行換算時間 `[s/人]`
- `f_congestion`: ブース近傍の重み付き混雑度

`f_move` には待ち行列時間、ブロック待機時間、入場遅延時間を加えません。
`f_congestion` は添付コードと同じ `weighted_congestion_sum / congestion_weight_sum`
です。幸福度などは監査KPIであり、目的関数へ追加していません。

### 来場者エージェント

来場者の生成、目的地選択、歩行、待ち行列、体験、断念、幸福度の計算規則は変更して
いません。疲労、休息、ベンチ探索などの新しい状態や行動も導入していません。

`tests/test_objective_and_speed_invariance.py` で添付コードの目的関数式を固定し、将来の変更を
検出します。また、固定配置・内部列型・外周型・混合型の4配置を元コードと比較し、
2目的、全KPI、時系列が完全一致することを確認しています。

## 人が受け入れやすい配置の定義

全配置物を少数の直線列だけに限定しません。次の2種類を同格の「配置モチーフ」として
最終138変数から検出します。

- 会場内部の水平列・垂直列
- 実際の会場多角形の外周に沿う連続チェーン

このため、複数列、島、L字、外周配置、斜辺に沿う階段状配置、およびそれらの混合が
探索空間に残ります。通常ブースとベンチは共通の整列評価に含めますが、ベンチだけを
集める用途固有制約はありません。人手配置 `booths.yaml` も物理制約と整然さ制約を満たし、
探索可能空間に含まれることを回帰テストしています。

### 7つの独立した整然さ制約

| 制約 | 既定上限 | 意味 |
| --- | ---: | --- |
| `organization_nonmembership` | 0.30 | 内部列・外周モチーフのどちらにも属さない割合 |
| `motif_complexity` | 1.20 | 必要標準モチーフ数に対する実モチーフ数比 |
| `alignment_error` | 0.36 | 列基準線または外周共通セットバックからのずれ |
| `gap_variation` | 0.20 | モチーフ内の外周間隔のMAD比 |
| `orientation` | 0.25 | 列軸または外周内向きに対する通常ブース正面の不一致率 |
| `isolation` | 0.20 | 内部列・外周追従の近傍を持たない割合 |
| `front_clearance` | 0.00 | 通常ブース正面2セル通路の閉塞率 |

物理制約に加えて、この7成分を個別の不等式制約としてNSGA-IIへ渡します。目的関数が
良くても整然さ違反を相殺できません。`orderliness` は各成分を上限で割った最大値で、
1以下なら全成分を満たします。

## 初期集団と遺伝演算

初期集団は `booths.yaml` を種にせず、物理制約と整然さ制約を満たすランダム個体のみで
生成します。内部列型50%、外周型20%、混合型30%を既定の構成比とします。生成後はすべて
通常の138整数変数として扱うため、進化中の探索次元は削減されません。

突然変異は次の3段階を混合します。

| 種類 | 条件付き確率 | 操作例 |
| --- | ---: | --- |
| 局所 | 55% | 1～4配置物の微小移動・向き反転 |
| 中規模 | 30% | モチーフ内交換・平行移動・回転 |
| 大域 | 15% | 区画再配置・鏡映・配置スタイル変更 |

候補が制約を壊す場合はその操作を採用せず、再試行または元個体を維持します。これは子個体
生成時の実行可能性保持であり、最適化後の修復ではありません。

## Memetic探索

5世代ごとに、実行可能な非劣解から重複なしで最大10個体をランダム選択し、各親について
互いに異なる実行可能10近傍を通常のシミュレーションで評価します。最大100近傍を現在の
集団と統合し、通常のNSGA-II環境選択で個体数を元へ戻します。

実行履歴は `memetic_history.csv` に保存します。実動作テストでは第5世代に非劣解3個体から
30近傍が追加評価されました。

## シミュレーションの意味を変えない高速化

代理モデル、時間刻みの粗粒化、来場者数削減、早期打切り、近似目的関数は使用しません。

- 配置評価をプロセス並列化し、各ワーカーで静的会場・来場者表を一度だけ構築
- BLAS/OpenMPの内部スレッドを1にしてプロセスとの二重並列を防止
- GA中は目的関数に不要なヒートマップ・フレーム・時系列配列だけ収集しない
- 完全に同じ整数配置の厳密評価結果をワーカー内キャッシュ
- 静的な群衆距離場・経路インデックスを再利用
- Manhattan近傍マスクを同値なNumPy演算へ置換
- 経路下降カーネルをNumba JIT化し、Numbaが無い環境では同値なPython実装へフォールバック
- 初期集団を個体単位で決定的に並列生成し、評価用プロセスPoolをそのまま再利用
- 5世代ごとのMemetic近傍を親個体単位で決定的に並列生成
- 整数遺伝子が完全一致する個体の物理・整然さ制約値を、上限付き厳密キャッシュで再利用
- 物理制約と整然さ制約でブース本体・受付・待機列・正面通路の幾何情報を共有
- 整然さ判定内で中心、寸法、列候補、外周線分、グループ分けを共有・静的キャッシュ
- 各変異操作内ですでに実行済みだった同一の実行可能性判定だけを削除

時系列収集を切った軽量評価と完全収集評価で、2目的と全KPIが一致するテストを同梱して
います。初期集団とMemetic近傍にはタスク単位の決定的seedを割り当て、Poolの`starmap`が
保証する入力順で統合します。同一目的値を持つ等価遺伝子のタイブレークを除き、ワーカー数を
変えても探索品質を変えません。乱数ストリームをタスク単位へ整理したため、更新前プログラムと
同じseedを与えたときの世代軌跡そのものは一致しませんが、初期化・遺伝演算・近傍探索の確率
分布、評価数、目的関数、制約、シミュレーションは変更していません。

付属設定による小規模確認（4個体・5世代、同一マシン）では、1ワーカー63.3秒に対して
2ワーカー34.4秒でした。両実行の4つのパレート目的値と、第5世代の追加評価40件は一致しました。
実際の短縮率はCPUコア数と個体評価時間に依存します。

## 実行方法

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python scripts/run_optimization.py --pop 100 --gen 1000 --workers 8
```

テスト:

```bash
python -m unittest discover -s tests -v
```

制約・遺伝演算・Memeticの調整例:

```bash
python scripts/run_optimization.py \
  --max-organization-nonmembership 0.30 \
  --max-motif-complexity 1.20 \
  --max-alignment-error 0.36 \
  --max-gap-variation 0.20 \
  --max-orientation-error 0.25 \
  --max-isolation 0.20 \
  --max-front-clearance-violation 0.0 \
  --mutation-individual-prob 0.70 \
  --mutation-local-weight 0.55 \
  --mutation-meso-weight 0.30 \
  --mutation-macro-weight 0.15 \
  --memetic-interval 5 \
  --memetic-parents 10 \
  --memetic-neighbors 10
```

## 主な出力

- `pareto_solutions.csv`: 2目的のパレート解
- `direct_138_designs.csv`: 138設計変数と整然さ7成分
- `direct_138_method.json`: 表現、制約、遺伝演算、Memetic設定
- `memetic_history.csv`: Memetic実行世代と追加評価数
- `comparison_table.csv`: 代表解、ランダム初期解、`booths.yaml` の同一条件比較
- `orderliness_diagnostics.json`: 各配置物を説明する列・外周モチーフ
- 代表配置JSON、ヒートマップ、パレートフロント、HV推移、時系列グラフ

本方式の中心実装は `src/direct_optimization.py`、実行入口は
`scripts/run_optimization.py` です。
